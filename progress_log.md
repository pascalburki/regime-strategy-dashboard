## August 4 2026
Built a regime-based trading strategy using HMM's hidden states on natural gas (NG=F): 100% exposure in calm state, 40% in moderate state, 0% in stress state
Initial backtest (HMM trained on full 2018-2023 dataset): strategy returned +0.98 (log) vs. buy-and-hold's -0.24, Sharpe 0.71 vs. -0.06
Retested with a more honest split: HMM trained only on 2018-2020, predicting forward on 2021-2023 (data it never saw)
Key finding: the realistic test reversed the result entirely, strategy returned -0.96 vs. buy-and-hold's -0.01. The original strong result was substantially inflated by look-ahead bias, since the full-period model effectively "knew" about the 2022 crisis before classifying earlier periods, and the regimes learned from 2018-2020 didn't generalize well to the fundamentally different conditions of 2021-2023
Script: strategy/august4_regime_strategy.py

## August 5 2026
Built a walk-forward HMM strategy on SPY (2000-2023 data, monthly retraining from 2015 onward) to eliminate look-ahead bias
Initial attempts had severe convergence failures using random HMM initialization. Fixed by using diagonal covariance and explicit, sensible starting parameters instead of random ones — 0% convergence failures after the fix
Tested 5 exposure combinations against the same predictions. Best result: {state 0: 1.2x, state 1: 1.0x, state 2: 0.0x} — full exposure in calm/moderate regimes with modest leverage in state 0, zero exposure in the stress regime
Final result: strategy return 1.3531 vs. buy-and-hold 1.1110, Sharpe 0.9012 vs. 0.6612, max drawdown -0.3272 vs. -0.4112 — beats buy-and-hold on every dimension, with genuine walk-forward validation (no look-ahead bias)
Script: strategy/august5_spy_walkforward.py

## August 11 — Corrections to August 4/5/6 and the dashboard

**Bug found: August 4's exposure dict was reused across two unrelated HMM fits.** `august4_regime_strategy.py` fit one HMM on the full 2018-2023 period and a separate HMM on 2018-2020 only, then applied the *same* hardcoded `exposure = {1: 1.0, 0: 0.4, 2: 0.0}` to both — assuming state numbering meant the same thing in both fits, with no check. This is the same hardcoded-label bug documented and fixed repeatedly in the K-means repo, recurring here. Additionally, the script used default random HMM initialization and never checked `model.monitor_.converged` — the exact setup August 5 later discovered has "severe convergence failures." Neither fit's convergence was ever verified. It also skipped `StandardScaler`, inconsistent with the established fix for `GaussianHMM.fit()`.

**Fix applied:** rewrote as `august4_regime_strategy_FIXED.py` — added `StandardScaler` (scaler fit only on train data for the realistic split, to avoid leakage into the test set), switched to the explicit stable HMM initialization from August 5, added convergence reporting for both fits, and replaced the shared hardcoded exposure dict with independent label derivation per model (ranking states by volatility for "calm," then by return for "stress" vs. "moderate"), with a warning if the two models' derived label sets don't match. **Not yet rerun — the original August 4 numbers above (+0.98/-0.24 and -0.96/-0.01) should be treated as unverified until this fixed version is run and compared.**

**Bug found: `august6_portfolio_regime_strategy.py`'s dashboard "core finding" was misattributed.** `app.py` displayed "diversification benefit collapses once uniform correlation exceeds 0.879" as this project's finding. That figure is not computed anywhere in this codebase — it belongs to the separate Regime-Based Risk Instability project's rolling-correlation analysis. Fixed by replacing it in `app.py` with a stat actually computed from `correlation_matrix.csv` (max pairwise correlation, currently 0.93 for SPY/QQQ), with the 0.879 figure kept only as an explicitly-attributed reference to the other project.

**Verified directly from CSVs:** the dashboard's headline strategy numbers (0.57 vs. 0.44 return, 0.84 vs. 0.69 Sharpe) are accurate. Max drawdown, which wasn't previously reported, is -0.265 (strategy) vs. -0.264 (buy-and-hold) — essentially tied, not a strategy win, unlike the single-asset August 5 result. Also confirmed: the strategy/buy-and-hold comparison only covers 2020-01-02 to 2023-12-29 (1,039 days), shorter than the 2018-2023 range used in the Risk Analysis tab — now stated explicitly in the README and dashboard caption.

**Fix applied (August 5 and 6 scripts):** both walk-forward scripts now record each monthly refit's fitted `means_` and print a summary range per state at the end, so state identity holding across ~96 monthly refits is checked rather than assumed. Also added an inline note that convergence failures currently silently drop that month's data from both the strategy and buy-and-hold series (0% failure rate observed so far, so no effect on current numbers, but worth knowing if that ever changes).

**Open items:**
1. **Resolved — strict-volatility labeling decisively outperforms the original return-based tie-break.** Reran the realistic split (train 2018-2020, test 2021-2023) with both labeling rules on the exact same fitted model and predicted states — only the label-assignment logic differs. Return-based rule: return 0.0506, Sharpe 0.0595, drawdown -0.5201. Strict-volatility rule: return 0.6660, Sharpe 1.1389, drawdown -0.2846. This is not a small effect — 13x on return, 19x on Sharpe, roughly half the drawdown. Mechanism: the return-based rule assigns "stress" to the state with the most negative *average* return, but the strict-volatility rule assigns "stress" to the highest-volatility state instead — and the highest-vol state (state 2, vol 0.0596) has a less-negative average return than the moderate-vol state (state 1, vol 0.0363) here, meaning it likely contains the real tail-risk days even though its average looks tamer. Cutting exposure by volatility catches the actual dangerous days; cutting by average return sign can hide them. **Adopting strict-volatility labeling as the standard going forward** — this also brings this script in line with the K-Means project's own `derive_labels` convention, which already ranks purely by volatility. The return-based result is kept below as a documented comparison, not deleted, since the size of the gap between the two rules is itself a real finding.
2. **Resolved.** State-identity check, run twice on August 6, real problem confirmed. August 5 (SPY walk-forward, 108 windows): all three states cleanly separated, zero range overlap — state identity held throughout. **August 6 (portfolio strategy, 48 windows): State 1's volatility range (0.0144–0.0212) is entirely contained within State 2's range (0.0137–0.0506).** This is reproducible — confirmed identical (to the meaningful decimal) across two separate runs, so it's a real property of the fitting process, not a one-off fluke. This means "moderate" and "stress" likely didn't hold a consistent identity across all 48 monthly refits — some months' "moderate" state may have had volatility as high as other months' "stress" state. The dashboard's headline numbers (0.57 vs 0.44 return, 0.84 vs 0.69 Sharpe) are still accurate as computed, but now carry a real, demonstrated caveat about what the underlying state labels actually mean month to month — not a hypothetical one.
3. **Resolved.** Reproducibility of the August 6 portfolio backtest, confirmed. Ran twice independently. Every headline number (buy-and-hold return, strategy return, both Sharpe ratios, both max drawdowns) matched exactly across both runs. State-range figures differed only at the 7th-10th decimal place — floating-point noise, not a substantive discrepancy.

**All three open items from this audit are now closed.** The one genuinely important finding to come out of the process: which labeling rule you use for "stress" changes the realistic-split strategy result by an order of magnitude, and volatility-based labeling is both more defensible and more consistent with the rest of this project's conventions.

## August 11 (cont'd) — August 4 rerun: the headline finding was wrong, corrected version is better

Ran `august4_regime_strategy_FIXED.py`. Both HMM fits converged cleanly (10 iterations each). State labels derived correctly for the full-period model (calm/moderate/stress cleanly separated by volatility: 0.017/0.037/0.062). For the train-only model, volatility and return-direction don't point to the same state — state 1 (vol 0.036) has the more negative return while state 2 (vol 0.060, higher) is closer to flat. The label logic currently defines "stress" as the most-negative-return state among the two higher-vol states, not strictly the highest-vol state — worth being explicit about, since these two definitions coincided in the full-period model but not here.

**This ambiguity is not just a footnote — it directly underlies the headline drawdown finding below.** Which state gets zero exposure depends on which label rule is used, and the two rules disagree here. This has not been independently re-derived under the alternative (strict-volatility) rule to see whether the drawdown result would change; it should be, before this finding is presented as settled.

**Verified numbers:**
- Full-period (biased): strategy +0.5949, buy-and-hold -0.2397, Sharpe 0.4618 vs -0.0608
- Realistic split (train 2018-2020, test 2021-2023): strategy +0.0506, buy-and-hold -0.0099, Sharpe 0.0595 vs -0.0043, **max drawdown -0.5201 vs -1.5814**

**The finding changes, not just the numbers.** The original entry (August 4) claimed the realistic split "reversed the result entirely," with the strategy losing badly (-0.96) where buy-and-hold barely lost (-0.01). That does not hold up under either labeling rule. Using the now-adopted strict-volatility labeling: strategy return +0.6660 vs. buy-and-hold's -0.0099, Sharpe 1.1389 vs -0.0043 — the strategy substantially outperforms, not just edges out, buy-and-hold in the honest test. (Under the original return-based tie-break, the edge was much thinner: +0.0506 vs -0.0099 return, Sharpe 0.0595 vs -0.0043 — see "Open items" below for why strict-volatility labeling was adopted instead.)

**The real story in the realistic split is still drawdown, and it's stronger under strict-volatility labeling too.** Buy-and-hold's max drawdown (-1.58 in log terms) is roughly 5.5x the strategy's under strict-volatility labeling (-0.28), compared to roughly 3x under the original return-based rule (-0.52). The strategy's 0% exposure during the correctly-identified highest-volatility state avoids more of the real 2022 spike/2023 crash than the original labeling caught.

Buy-and-hold return numbers are consistent with the original entry in both periods (-0.24 → -0.2397 biased; -0.01 → -0.0099 realistic), as expected since buy-and-hold doesn't depend on the model at all — a useful sanity check that the rest of the pipeline (data, date ranges) didn't change, only the model fitting did.
